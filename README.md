# متجر البشرى

متجر ملابس يعمل بنظام الدروب شيب لعملاء داخل السودان وخارجه، مبني على Cloudflare:

- **Cloudflare Workers** يشغّل الخادم (Hono + TypeScript)
- **D1** قاعدة البيانات (المنتجات والطلبات والإعدادات)
- **R2** لتخزين صور المنتجات وإشعارات تحويل بنكك
- **Cron** كل ساعة لمزامنة حالة الطلبات من الموردين وإلغاء الطلبات غير المدفوعة

## الواجهة والتصميم

- **المتجر** (`public/`): HTML وCSS وJavaScript بدون أي خطوة بناء، يعمل من اليمين لليسار، وخطوطه (Cairo وLalezar) مستضافة محلياً.
  - الملابس معلقة على رف بأسلوب ثلاثي الأبعاد؛ القطعة المختارة تتقدم وتدور دورة كاملة عند التبديل (يظهر ظهرها أثناء الدوران) ثم تتأرجح على العلاقة.
  - صفحة المنتج: القطعة على علاقة، وخلفها قطع القسم بضبابية، وزر «أمام / خلف» يقلبها، والألوان تبدّل الصور.
  - السلة، وصفحة إتمام الطلب، وصفحة متابعة الطلب مع رفع إشعار بنكك.
- **لوحة التحكم** على `/admin/`: الطلبات (مراجعة إشعارات بنكك وقبولها)، والمنتجات (إضافة منتج بألوانه ومقاساته وصوره الأمامية والخلفية)، والأقسام، والإعدادات.
## الملابس ثلاثية الأبعاد (WebGL)

كل صورة ملابس تتحول في المتصفح إلى قطعة ثلاثية الأبعاد معلّقة على علّاقة خشبية فوق رف معدني، مع إضاءة وظل على الجدار:

1. **إزالة الخلفية** (`public/js/garment-image.js`) للخلفيات البيضاء أو الفاتحة، وللمربعات «الشفافة» المطبوعة في الصورة. تعمل بتعبئة من حواف الصورة تتوقف عند حدود القطعة، ثم تنظيف الحواف. يوجد خيار لإزالة المانيكان في الملابس الملونة.
2. **الحجم:** سماكة القطعة تُستخرج من شكلها (تنتفخ من الحدود للداخل)، والظهر سطح منفصل بصورة الظهر أو بظهر سادة يُولَّد تلقائياً.
3. **قماش فيزيائي** (`public/js/garment3d.js`): جدار جانبي يغلق الفراغ بين الأمام والظهر من كل الجوانب ويتحرك مع القماش، وشبكة نوابض مثبتة على العلّاقة تتموّج مع النسيم، وتتطاير أطرافها عند الدوران، وتتأرجح، وتتحرك عند تمرير الماوس عليها.
4. **المشهد** (`public/js/rack3d.js`): الرف والإضاءة والظلال، والسحب لتدوير القطعة في صفحة المنتج. على الأجهزة التي لا تدعم WebGL يعمل الرف القديم بأسلوب CSS تلقائياً.

**تصوير المنتجات (مهم للواقعية):**
- خلفية بيضاء أو رمادية فاتحة سادة، وإضاءة متساوية بلا ظلال قوية، والقطعة كاملة داخل الصورة دون قص.
- الأفضل: القطعة مفرودة أو على علّاقة أو بأسلوب «المانيكان الشبحي». **لا تستخدم صوراً على موديل** (يبقى الشخص في الصورة).
- صورة للأمام وصورة للظهر، بدقة 1500 بكسل على الأقل.
- **صور على موديل أو مانيكان:** فعّل خيار «الملابس فقط» عند رفع الصورة. نموذج ذكاء اصطناعي لتحليل الإنسان (SegFormer B2 Clothes) يعمل في متصفح لوحة التحكم، فيحدد الملابس (علوي، بنطلون، فستان، تنورة، حزام، شال) ويزيل الوجه والشعر واليدين والرجلين والأحذية. يُحمَّل النموذج مرة واحدة (نحو 27 ميجابايت). إن تعذّر تحميله تُستخدم طريقة بسيطة تزيل المانيكان الأبيض فقط.
- تجنّب صور مواقع الصور المجانية التي عليها علامة مائية (مثل pngtree)، فالعلامة تظهر على القطعة والصورة محمية بحقوق.

**إزالة الخلفية بالذكاء الاصطناعي:** للملابس البيضاء على خلفية بيضاء وللحالات الصعبة، تستخدم لوحة التحكم نموذج Bria RMBG 2.0 عبر Workers AI في Cloudflare (`"ai"` في `wrangler.jsonc`)، بتكلفة نحو 0.018$ للصورة، ولا يحتاج مفتاحاً إضافياً غير حساب Cloudflare. التشغيل المحلي `npm run dev` يعمل بدونه، أما `npm run dev:ai` فيحتاج تسجيل الدخول إلى Cloudflare.

**ارتفاع الرف** يتكيف تلقائياً مع طول القطعة (تيشيرت أو عباية طويلة). مكتبة three.js مضمّنة في `public/vendor/three.min.js`، ويُعاد بناؤها بالأمر `npm run vendor:three`.
- **الأقسام:** تيشيرتات، جاكيتات، هوديز، بنطلونات وجينز، عبايات نسائية، جلاليب سودانية، قبعات وطواقي. يمكن إضافة أي قسم جديد من لوحة التحكم.
- **صور تجريبية:** في `public/demo/`، وتُولَّد بالأمر `node scripts/garments.mjs`. البيانات التجريبية في `seed/demo.sql` للتجربة المحلية فقط، ولا تُشغَّل على المتجر الفعلي.

## طرق الدفع

| العميل | الطريقة | سير العمل |
|---|---|---|
| داخل السودان | بنكك (`bankak`) | يظهر للعميل رقم الحساب، فيرفع صورة الإشعار، ثم تراجعها وتوافق عليها من لوحة التحكم |
| خارج السودان | بطاقة (`card`) عبر Stripe | يُحوَّل العميل لصفحة الدفع، ويُؤكَّد الطلب تلقائياً عند الدفع |

الدولة `SD` تعني «داخل السودان» والأسعار فيها بالجنيه، وما عداها «خارج السودان» والأسعار بالدولار. السعر الأساسي لكل منتج بالدولار، ويُحوَّل للجنيه بسعر الصرف في الإعدادات، ويمكن تحديد سعر ثابت بالجنيه لأي مقاس.

## حالات الطلب

`pending_payment` ← `awaiting_verification` (بنكك) ← `confirmed` ← `sent_to_supplier` ← `shipped` ← `delivered`، ويمكن الانتقال إلى `cancelled` من أي مرحلة قبل التسليم.

## الموردون

كل مورد له «محوّل» (adapter):

- `manual`: يُرسَل الطلب للمورد يدوياً (مثلاً بالواتساب)، ثم تحدّث الحالة من لوحة التحكم.
- `http_json`: ربط عبر API، يُرسل الطلب تلقائياً ويسحب حالة الشحن ورقم التتبع ويستورد المنتجات. يُضبط بـ `baseUrl` ومسارات الـ API في إعدادات المورد، ويوضع مفتاح الـ API في السر `SUPPLIER_<CODE>_API_KEY`.

إذا كان الـ API لمورد معيّن يختلف عن الشكل العام، يُضاف له ملف محوّل خاص في `src/suppliers/` يطبّق الواجهة `SupplierAdapter`. أرسل توثيق الـ API الخاص بالمورد ليُبرمج ربطه.

## التشغيل محلياً

```bash
npm install
cp .dev.vars.example .dev.vars      # ضع ADMIN_TOKEN
npm run db:migrate:local
npx wrangler d1 execute albushra-db --local --file seed/demo.sql   # منتجات تجريبية (اختياري)
npm run dev                          # المتجر: http://localhost:8787  — لوحة التحكم: /admin/ (بدون Workers AI)

```

## النشر على Cloudflare

```bash
npx wrangler login
npx wrangler d1 create albushra-db           # انسخ database_id إلى wrangler.jsonc
npx wrangler r2 bucket create albushra-media
npm run db:migrate:remote
npx wrangler secret put ADMIN_TOKEN
npx wrangler secret put STRIPE_SECRET_KEY          # عند تفعيل الدفع الإلكتروني
npx wrangler secret put STRIPE_WEBHOOK_SECRET
npm run deploy
```

بعد النشر:
1. عدّل `PUBLIC_URL` في `wrangler.jsonc` إلى رابط المتجر، واربط النطاق من لوحة Cloudflare.
2. في لوحة Stripe أضف Webhook على `https://<النطاق>/api/payments/stripe/webhook` للأحداث `checkout.session.completed` و`checkout.session.async_payment_succeeded` و`checkout.session.async_payment_failed`.
3. من `PUT /api/admin/settings` اضبط: رقم حساب بنكك واسمه، وسعر الصرف، ورسوم الشحن، ورقم الواتساب.

> **تنبيه:** حساب Stripe يجب أن يُفتح في دولة يدعمها Stripe (مثل الإمارات أو بريطانيا أو أمريكا). إن كان الحساب في السعودية أو مصر فيمكن استبدال Stripe ببوابة أخرى مثل Tap أو Paymob، وذلك بتعديل `src/payments/`.

## واجهة الـ API

جميع المبالغ أعداد صحيحة: **الدولار بالسنت** (2000 = 20$) و**الجنيه بالجنيه الكامل**.

### للمتجر (عام)

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/config` | اسم المتجر وطرق الدفع والشحن لكل منطقة |
| GET | `/api/categories` | الأقسام |
| GET | `/api/products?region=sd&category=&q=&limit=&offset=` | المنتجات بعملة المنطقة (`region` = `sd` أو `intl` أو رمز الدولة) |
| GET | `/api/products/:slug?region=` | تفاصيل منتج |
| GET | `/api/variants?ids=1,2&region=` | أسعار عناصر السلة |
| POST | `/api/orders` | إنشاء طلب (انظر المثال أدناه) |
| GET | `/api/orders/:number?token=` | متابعة الطلب |
| POST | `/api/orders/:number/receipt?token=` | رفع إشعار بنكك (`multipart`: الحقلان `receipt` و`transactionId`) |
| POST | `/api/orders/:number/checkout?token=` | إعادة محاولة الدفع بالبطاقة |

```json
POST /api/orders
{
  "customer": { "name": "أحمد علي", "phone": "+249912345678", "country": "SD", "city": "بورتسودان", "address": "حي الثورة" },
  "items": [{ "variantId": 1, "quantity": 2 }],
  "paymentMethod": "bankak"
}
```

يُرجِع الطلب ورمز `accessToken` (يُحفظ في المتصفح لمتابعة الطلب)، ومعه بيانات حساب بنكك أو رابط الدفع `checkoutUrl` حسب طريقة الدفع. لا يوجد دفع عند الاستلام.

### لوحة التحكم (الترويسة `Authorization: Bearer <ADMIN_TOKEN>`)

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/admin/summary` | عدد الطلبات حسب الحالة |
| GET | `/api/admin/orders?status=&q=` | قائمة الطلبات |
| GET | `/api/admin/orders/:number` | تفاصيل الطلب وسجل أحداثه |
| GET | `/api/admin/orders/:number/receipt` | صورة إشعار بنكك |
| POST | `/api/admin/orders/:number/verify-payment` | `{ "approve": true }` لقبول تحويل بنكك أو رفضه |
| POST | `/api/admin/orders/:number/status` | `{ "status": "shipped" }` لتغيير الحالة |
| POST | `/api/admin/orders/:number/forward` | إرسال الطلب للمورد يدوياً أو إعادة المحاولة |
| POST | `/api/admin/orders/:number/note` | ملاحظة داخلية |
| GET/POST/PUT/DELETE | `/api/admin/products[/:id]` | المنتجات (الحذف يُخفي المنتج فقط) |
| POST | `/api/admin/products/:id/variants`، PUT `/api/admin/variants/:id` | المقاسات والألوان |
| POST | `/api/admin/media` | رفع صورة منتج (`multipart`: الحقل `file`) |
| POST/PUT/DELETE | `/api/admin/categories[/:id]` | الأقسام |
| GET/POST/PUT | `/api/admin/suppliers[/:id]` | الموردون |
| POST | `/api/admin/suppliers/:id/import` | `{ "markupPercent": 50 }` لاستيراد منتجات المورد (تُضاف مخفية للمراجعة) |
| GET/PUT | `/api/admin/settings` | الإعدادات |

## تجربة التطبيق (v0.2)

صُمّمت بمهارة **ui-ux-pro-max** (مثبتة في `.claude/skills/ui-ux-pro-max`)، ونظام التصميم المعتمد في `design-system/albushra-store/MASTER.md`:
- **شاشة بداية احترافية:** الشعار يُرسم (الخطاف ثم العلّاقة ثم الورقة)، ثم الاسم والشعار اللفظي، وشريط تقدّم مرتبط بالتحميل الفعلي للرف ثلاثي الأبعاد. في أندرويد تسبقها شاشة إقلاع أصلية بنفس اللون (بما فيها شاشة أندرويد 12+). على الموقع تظهر مرة واحدة في كل زيارة، وتُعرض للمراجعة عبر `?splash=hold`.
- **شريط تنقل سفلي زجاجي** (الرئيسية، الأقسام، المفضلة، السلة، طلباتي) مع عدّادات، ومساحات آمنة، وأهداف لمس بحجم 48px.
- **المفضلة** (`/favorites`)، و**طلباتي** (`/orders`)، و**شريط شراء ثابت** في صفحة المنتج، واهتزاز خفيف عند التأكيد.
- **هياكل تحميل** بدل مؤشرات الدوران، وانتقالات بين الصفحات، وظهور متتابع للعناصر، وحالات ضغط لا تُزيح المحتوى. كلها تحترم تقليل الحركة.
- **تطبيق ويب قابل للتثبيت (PWA):** `manifest.webmanifest` و`sw.js`، مع عمل دون اتصال للواجهة والصور.
- **التباين:** الأزرار الرئيسية بالأخضر الداكن `#1D7D1A`، لأن النص الأبيض على الأخضر الفاتح (2.3:1) لا يحقق معيار الوصول.

## جرّبها: غرفة القياس (v0.3)

صفحة `/tryon` (ومعها المفضلة) تعرض مانيكان عرض أبيض بلا ملامح، ورفاً سفلياً عليه المفضلة أولاً ثم قطع مقترحة:
- **شكل الجسم:** يختار العميل في أول زيارة واحداً من 8 أجسام (رجال: نحيف، متوسط، رياضي، ممتلئ؛ نساء: نحيفة، متوسطة، منحنيات، ممتلئة)، ويمكن تغييره في أي وقت. المانيكان مرسوم بـ SVG ويتغير عرض الكتفين والصدر والخصر والورك والفخذين (`public/js/tryon/mannequin.js`).
- **الارتداء:** الضغط على قطعة في الرف يجعلها تطير في قوس (GSAP MotionPath) وتدور ثم تستقر على المانيكان. القطع في طبقات: بنطلون، علوي، جاكيت فوقه، جلابية أو عباية تغطي الطقم، وقبعة أو طاقية. القطعة السابقة في نفس المكان تعود إلى علاقتها.
- **المقاس على الجسم:** يُقاس شكل القطعة من صورتها (عرض الكتفين والجسم) فيوضع العلوي على الكتفين والبنطلون على الخصر بالنسبة لجسم المانيكان المختار.
- **اطلب الطقم:** يعرض مجموع الطقم، ويضيف كل القطع إلى السلة مع اختيار المقاس لكل قطعة. الجسم والطقم يُحفظان في الجهاز.
- زر «جرّبها على المانيكان» في صفحة كل منتج يفتح الغرفة ويُلبس القطعة مباشرة (`/tryon?wear=slug`).
- **حدود الميزة:** المعاينة ثنائية الأبعاد بطبقات فوق المانيكان، وليست محاكاة قماش على جسم ثلاثي الأبعاد، والأكمام تبقى كما في صورة المنتج.

## الحركة

مكتبة `public/vendor/motion.min.js` (تُبنى بالأمر `npm run vendor:motion`) تجمع **GSAP** (ScrollTrigger وMotionPath وFlip وCustomEase) و**Lenis**:
- تمرير ناعم بعجلة الماوس (Lenis)، ويبقى اللمس أصلياً على الجوال.
- ظهور العناصر عند التمرير، وظهور اسم القطعة كلمة كلمة في الرف، وطيران شعار شاشة البداية إلى مكانه في الترويسة.
- مكونات منقولة من **React Bits** (ClickSpark للشرارات عند الضغط، وMagnet للأزرار الممغنطة على الكمبيوتر، وShinyText للنص اللامع)، بترخيص MIT + Commons Clause الذي يسمح باستخدامها داخل الموقع.
- كل الحركة تتوقف عند تفعيل «تقليل الحركة» في الجهاز (`public/js/motion.js`).

## تطبيق أندرويد تجريبي (APK)

`android/build-apk.sh` يبني تطبيقاً تجريبياً يعمل **دون إنترنت**:
- المتجر بالكامل داخل التطبيق (WebView)، والمنتجات مصدّرة من الخادم المحلي.
- طبقة `android/demo-api.js` تحل محل الخادم، فتعرض المنتجات وتحفظ الطلبات التجريبية في الجهاز.

```bash
npm run dev                          # في نافذة أخرى، مع بيانات تجريبية
API=http://localhost:8787 ./android/build-apk.sh   # → android/build/albushra-demo.apk
```

لا يحتاج Android SDK، فالأدوات (aapt2 وdx) تُحمَّل من Maven Central. التطبيق موقّع بشهادة تجريبية، ويُثبَّت بتفعيل «السماح بالتثبيت من مصادر غير معروفة».
للنسخة النهائية بعد نشر المتجر: ضع رابط المتجر في `REMOTE_URL` داخل `android/src/sa/bushra/store/MainActivity.java`، فيفتح التطبيق المتجر الحقيقي بدل النسخة التجريبية، ثم يُوقَّع بشهادة دائمة لنشره على Google Play.
مزايا التطبيق الأصلية: شاشة إقلاع بلون العلامة، وأيقونة متكيفة، وتلوين أشرطة النظام بعد شاشة البداية (عبر `window.BushraApp.systemBars`)، وزر الرجوع يغلق اللوحات المفتوحة أولاً، والاهتزاز.
